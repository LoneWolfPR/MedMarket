**Design decision — prescription + order model (2026-07-07, applies Day 3+).** Agreed with user before starting the domain work:
- **Prescription:** `user_id`, uploaded doc (→ **MinIO**; store the object key on the record, not the blob), physician name, medication name (**free text**, normalized lowercase/trim at the adapter boundary to match how the mock catalogs compare — a typo just yields no search results), a **`Strength` value object** = numeric value + **unit enum** (mg/ml/mcg/g…; mg vs ml not interchangeable, no conversion), and **`quantity`** (dose count — lives on the prescription because it's part of the prescription the patient holds; **replaces** the originally-proposed `duration`, which is dropped; no dosage-frequency modeling). The prescription's med name + strength ARE the `PharmacyClient.Search` input.
- **Order:** stays lean — `prescription_id`, **order-vocabulary** `status` only (e.g. `placed`/`confirmed`/`shipped`/`delivered`/`canceled`), which **pharmacy**, the pharmacy's returned **order id** + **tracking id**, **price paid**, and **`quantity`** (copied from the prescription at order time — prescription is source of truth — so the order records what was actually bought). No shipping-status column, **no shipment entity** — shipping vocabulary stays behind the `ShippingClient` adapter + workflow.
- **Status split (Temporal):** order lifecycle is durable in Postgres (order vocabulary only); fine-grained shipping detail is **Temporal workflow state**, not a DB table. **Signal in / query out:** mock-shipping webhook → backend endpoint → **signal** the order workflow → workflow updates its in-memory shipping status and, via an **activity**, writes the coarse order-status transition to Postgres at thresholds (first shipping event → `shipped`, `delivered` → `delivered`); shipping's `picked_up`/`in_transit`/`out_for_delivery` **map into** the order enum, never stored raw (hexagonal boundary — order domain takes no dependency on shipping's vocabulary). A **new status API endpoint** does a Temporal **query** to read the live shipping detail (real-world use: customer-support tooling). Queries only work while the workflow is open (+ retention), so the endpoint **falls back to the Postgres order status** for completed/aged-out orders.

## Conventions

- All external dependencies accessed through port interfaces in ports/outbound/
- Adapters implement port interfaces, wired together in cmd/server/main.go
- Tests use testcontainers-go for integration tests needing Postgres
- golangci-lint must pass before committing
- Idiomatic Go is an explicit goal — the user is learning Go from a JS/TS/PHP/Java (OO) background. Favor the idiomatic Go construct (first-class functions/closures where a thing is essentially one behavior, e.g. middleware; small interfaces; struct+constructor only when a type holds dependencies *and* exposes multiple behaviors or satisfies an interface). Principle: reach for the smallest construct that fits, not "structs everywhere." When a choice diverges from OO-language habits, call it out and explain the Go reasoning rather than silently picking.
